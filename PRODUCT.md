# Product

## Platform

web

## Stack

Kotlin Multiplatform with Compose Multiplatform (Wasm + JS targets), Material Design 3, Gradle 9.6.1

## Users

- **Recruiters and hiring managers** evaluating Mohamed for Android/KMP developer roles
- **Potential clients** seeking freelance mobile development expertise
- **Technical collaborators** exploring open-source contributions or partnership opportunities

Visitors arrive with specific intent: assessing technical capability, reviewing project portfolio, or initiating contact. The site must communicate competence quickly and provide clear pathways to engagement.

## Product Purpose

A personal portfolio website that showcases Mohamed Gamal Abdelwahab's technical skills, project experience, and professional background as an Android/KMP developer. Success means visitors leave with confidence in Mohamed's capabilities and take action (contact, connect, hire).

## Positioning

Cross-platform mobile development expertise with proven delivery of production applications. Differentiator: hands-on experience with KMP, Compose Multiplatform, and modern Android architecture patterns, demonstrated through real-world projects across healthcare, news, and messaging domains.

## Operating Context

Visitors typically arrive via LinkedIn, GitHub profile links, or direct URLs from resumes. They spend 30-60 seconds scanning before deciding to engage further. The portfolio must work across devices, load quickly, and present information hierarchy that respects this attention window.

## Capabilities and Constraints

- Sections: Hero, About, Skills, Projects, Contact
- Responsive layout (mobile/desktop)
- Smooth scroll navigation between sections
- Project showcase with tech stack tags and GitHub links
- Contact information and social links
- All content is currently hardcoded (no CMS or backend)
- Single-page application structure
- Deployed to GitHub Pages

## Brand Commitments

- Professional, technical tone matching developer portfolio conventions
- No binding color palette or visual style constraints - open to bold redesign
- No external dependencies for content management
- GitHub Pages deployment constraint

## Product Principles

1. **Technical credibility first** - Every design decision must reinforce developer competence
2. **Scannable hierarchy** - Information density respects 30-60 second visitor attention
3. **Action-oriented** - Clear pathways to contact and engagement
4. **Cross-platform consistency** - Identical experience across devices
5. **Minimal dependencies** - Lean architecture aligned with developer ethos

## Accessibility & Inclusion

- Keyboard navigation support
- Sufficient color contrast for readability
- Responsive design for various screen sizes and devices
